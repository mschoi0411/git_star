## 프로젝트 성격

`mattpocock/skills`는 일반 애플리케이션보다 AI 코딩 에이전트용 작업 지침을 모은 저장소에 가깝다. 핵심 산출물은 Markdown으로 작성된 스킬이며, TDD, 코드 리뷰, 디버깅, 설계와 생산성 흐름을 다룬다.

README에는 Claude Code, Codex, GitHub Copilot, Gemini CLI와 기타 에이전트를 위한 설치 방법이 안내되어 있다. 저장소에는 플러그인 메타데이터, 버전 관리용 Node.js 설정과 일부 유지보수용 Shell 스크립트도 포함되어 있다.

원본 저장소를 복제하거나 설치하지 않았으며, 원본 스크립트와 스킬을 실행하지 않았다. 외부 패키지와 플러그인도 설치하지 않았다.

## 직접 작성한 작업

이 실습에서는 실행 예제 대신 독자적인 [`safe-repo-lab`](project/safe-repo-lab/SKILL.md) 스킬을 작성했다. 이 스킬은 공개 저장소를 하나씩 안전하게 조사하기 위해 다음 흐름을 정의한다.

1. 학습 범위와 승인 지점 설정
2. 공식 원문과 고정 버전 검증
3. 설치 및 실행 위험 검토
4. 원본과 결과물의 격리
5. 최소 실험과 실제 결과 기록
6. 보고서 작성과 민감정보 제거
7. 자원 정리 후 다음 저장소 승인

스킬의 구성은 작은 지침을 조합해 에이전트 작업 품질을 높인다는 일반적인 아이디어에서 영감을 받았다. 문장과 세부 절차는 이번 10개 저장소 실습 목적에 맞게 새로 작성했으며, 원본 스킬 문구를 복제하지 않았다.

## 위험과 판단

원본 설치는 에이전트의 사용자 설정 경로를 변경하거나 자동 업데이트를 활성화할 수 있다. 또한 일부 스킬은 파일 작성, Git 작업, 이슈 트래커 또는 외부 도구 사용을 유도할 수 있다. 이번 목표에는 전체 설치가 필요하지 않아 정적 조사와 독자 문서 작성만 수행했다.

## 한계

사용자가 독자 스킬 작성만 선택했으므로 원본 스킬 적용 전후의 실행 시간, 코드 품질 또는 오류율 비교는 수행하지 않았다. 따라서 이 문서는 기능 검증 보고서가 아니라 저장소 성격 조사와 자체 스킬 제작 결과를 기록한 것이다.

## 배운 점

- 에이전트 스킬은 실행 프로그램이라기보다 반복 가능한 작업 규칙에 가깝다.
- 트리거, 단계별 승인, 금지 행동과 출력 형식이 분명해야 재사용하기 쉽다.
- 제3자 지침은 자동 실행하지 않고 현재 목표와 안전 경계에 맞게 검토해야 한다.
- GitHub에는 원본 저장소 복제본보다 직접 작성한 스킬과 조사 근거를 게시하는 편이 이번 포트폴리오 목적에 맞다.

## 현재 판정
